# 千鱼 0.3.14 程序说明

本项目只负责 QQ 大肥鱼/千鱼：基于 MaiBot 1.3.19 二次开发，DeepSeek API 为后端，不引入 DeepSeek Harness。Windows 开发测试版；完整全新电脑安装与轻量云迁移尚未验收。

## 0.3.14 人物身份、防循环与记忆互通

普通群聊根据 QQ 头像与大肥鱼角色自称的双重证据识别鱼，写入独立人物身份记忆；只有被确认的鱼才受同话题三轮回复上限约束，分段或表情算一轮，部分送达也计入，完全失败不计。连续呼叫、话题窗口过期、改摘要和重启不能绕过；对方连续安静十分钟，或非鱼用户成功发起明确新话题后恢复。未知用户不默认限三轮。识图关闭或视觉服务不可用时保持未知，使用者可在“人格与记忆”纠正鱼/真人/重新判断。角色识别不是机器身份认证，可能误判，候选视觉检查会产生 API 费用。

自动长期记忆启用时，私聊与群聊默认互通；同一平台、机器人账号和对话者账号关联近期历史与长期检索，不按昵称合并。近期历史不等待聊天摘要；全局长期候选经过真实会话和人物来源校验后再送给 Planner/Replyer，不带入别人的私聊或未知来源。可用“私聊与群聊互通记忆”关闭。本版不迁移或重写旧记忆数据库；纯净新实例仍无角色、风格、知识或个人记忆，自动长期记忆仍默认关闭。

隔离核心接本地模拟 QQ/模型已验证三轮限制、重启保留及双向历史注入；合成长期记忆验证原生检索和回复参考链路。没有发送真实 QQ 验收消息或请求付费模型。私聊和高级共享专注模式不使用普通群聊的三轮话题限制。

## 历史：0.3.13 中性纯净版与安装升级

## 0.3.10 本机自然追问修复

实际日志确认：上一轮完整回答被裁决为 keep_open=false，成功发送后程序立即删除活动话题；下一条追问因此没有获得语义判断资格，并非模型已经判断追问无关。现在将“当前回答完整”和“会话结束”分开：普通回答成功后仍保留三条滚动追踪，只有明确收束的 action=end、三条未命中或超时才关闭。skip 不会因 keep_open=false 提前关闭。

每次裁决除主题摘要、参与者、近期上下文和当前发言外，额外提供上一条实际问题、实际发出的回答及对话者，理解代词、省略、条件变化和接梗；不要求重复呼叫词或原话关键词。不会为了延续话题强行追问。原有命中即替换后续三条、排队消息计入、不累加旧余量的规则保留。

28 项针对性单元回归通过；隔离原生核心与模拟 QQ/模型验证完整回答后的隐喻追问、省略追问、明确结束和原三条窗口边界，见 verification/topic-followup-acceptance.json。本机概率仍为 5%，个人资料和现有 0.3.7 分享包保留。本轮未发送真实 QQ 验收消息或请求付费模型；模拟裁决验证调用链，不等于真实模型语义质量验收。

## 0.3.9 本机三条消息滚动窗口

相关性仍由模型判断，本地只计数。每个群的话题最多追踪接下来的三条有效群友消息，连续三条均未触发有价值的续聊，就关闭追踪，后续消息不再获旧话题判定资格。明确呼叫和无活动话题时的新话题概率仍独立工作，模型也可提前结束话题。

窗口按触发消息滚动替换：A 命中后，新窗口就是 B/C/D；B 命中则是 C/D/E。旧余量不累加，每条按顺序只裁决一次；回复生成时已经排队的消息同样计入新窗口，不等生成完成后另找三条。命中时即替换计数锚点，发送成功回调不再追加三条，重复回调、消息重放、命令、通知与自身回声不续期。判定失败同样占用本条机会，不无限重试。

21 项话题/设置单测及 4 项图片回归通过，原生核心接本机模拟模型/QQ 验证第一/第二/第三条命中的替换边界，并核对第四条不再请求旧话题判定。证据 verification/topic-window-acceptance.json、topic-window-unit.log 及部署报告。本机概率仍为 5%，分享包仍为 0.3.7，未重打包。三条约束的是后续判定范围，实际回复和必要工具仍会产生独立模型调用。

## 0.3.8 本机三种接话入口和话题结束点

本机普通群聊使用三个独立入口：回应明确呼叫；延续尚未结束且确实在与鱼交流的话题；无人呼叫、没有活动话题时按客户端滑块原值尝试开启新话题。滑块 0.25 就是 25%，没有额外乘数；0 不主动开新话题，但仍可回应呼叫和续聊，1 也不会切换逐条回复。客户端用百分比显示，步长 1%。

每次先由独立语义裁决选择 reply、skip 或 end，再准入原生工具与回复。相关不代表必须回复，其他人互聊、附和、重复或无需补充时可以略过。0.3.10 起，完整回答不再立即关闭追问窗口；明确告别、要求停止等收束可静默结束。关闭后不会从历史中自动复活话题，3 分钟无后续活动也会结束。话题状态只在真实回复发送成功后开启或更新。裁决失败会记日志，不退回无条件回复。

本机已按旧实际新话题机会迁移：旧滑块 0.5 乘旧系数 0.1 等于 5%，新版直接显示 5%（0.05）。人格与记忆等资料保留。证据为 verification/topic-lifecycle-acceptance.json 及相应日志，19 项针对性回归和隔离原生核心/UI 通过；模拟裁决不代表实际模型语义质量已验收。0.3.8 尚未重打纯净包，现有分享包及 PDF 仍为 0.3.7，其旧 0/1 档说明不能当作新版客户端规则。

## 0.3.7 话题接话与操作手册历史说明

0.3.7 为新实例从通用模板生成 `social/topic-reply.json`，默认启用，已有实例的开关与呼叫词保留。中间档不再按积压消息条数等待，改为收到新发言后由原生 Planner 判断语义关联：被关键词/@叫到优先接话，延续最近实际参与的话题，无关闲聊偶尔参与。默认呼叫词为千羽、千鱼、肥鱼、大肥鱼；同人紧邻补充最多短等 0.8 秒，换人或提及立即判断。无关插话机会为 `0.1 × 滑块值`，并在机会或实际回复后间隔至少 90 秒；机会不等于保证回复。

普通闲聊一旦略过就只作历史上下文，不留待补答；一个话轮只接当前话题，成功回复后结束，拦截重复 reply 和指向旧消息的 reply。保留原生记忆、图库、表情工具和发送守卫。0 静默、1 逐条、私聊及 Focus 共享模式保持既有行为。没有上述启用文件的实例不启用本补丁；设置文件修改后重启核心。

12 项针对性回归及原生核心连接模拟模型/QQ 的验收通过，证据在 `verification/topic-reply-*.json` 与相应日志。没有为验收额外向真实 QQ 发消息或请求付费模型；模型的实际语义判断质量仍需实际聊天观察。逐条判断可能增加模型调用。纯净 ZIP 已纳入该功能和“操作手册.pdf”“操作手册.md”，接收者安装后生成自己的独立实例；不从原使用者的实例取模板。

## 0.3.4 群聊接话滑块

打开“人格与记忆 → 群聊主动接话”，用 0～1 滑块调节，步长 0.05，点击“保存接话频率”。运行中可单独保存，无需停止核心，下一轮自动生效；普通配置保存与重启不会覆盖它。旧实例保留原值。

- 0：不回复群消息，包括 @ 和提及；私聊不受影响。
- 0～1 之间：越大越积极，保留话题判断，不是逐条消息的回复概率。
- 1：逐条回应已接入群的有效新消息，没有提及也回复；生成期间收到的消息按顺序排队，自身回声、命令和通知不作为群友发言。模型或发送失败会明确记日志，不能保证故障期间送达。

1 档直接使用原生 Replyer 与发送链路，保留人格、文件知识、风格及发送守卫；不再让 Planner 选择 stop/wait，因此也不走普通 Planner 的工具规划。近期上下文仍会裁切，不在此模式下用 Planner 前缀生成滚动摘要。需要自然聊天和工具自主选择时使用中间档位。1 档会增加模型调用。

设置源为个人 `fatfish.json` 的 `group_reply_frequency`，同步到 `chat.reply_timing.talk_value/reply_each_message`；页面全群设置会关闭旧动态频率规则，避免旧规则覆盖滑块。接口 `/api/participation` 仅接受此字段，沿用本机认证，不修改密钥、人格和聊天范围。为实现真正逐条回复，对锁定的 MaiBot 作了有范围的本地修改，文件清单见 `upstream.lock.json`。验证入口为 `tests/test_participation.py` 与 `scripts/verify_participation.py`。

## 使用入口

请从上一层的“启动千羽.cmd”打开；首次安装使用“安装千羽.cmd”。桌面快捷方式仍叫“千羽”，保留现有使用习惯。首次运行联网下载官方 NapCat，由你扫码登录小号；填写自己的 API、聊天范围，然后启动核心。QQ 在线和核心就绪是不同状态。

上一层“我的资料”提供中文文件夹入口，每个入口都指向实际资料，编辑后就是原文件。详见 templates/资料库使用说明.md。短背景和人格可在页面填写；更长资料直接放文件，不受页面输入框字数限制。

## 两种记忆的路径

- 人格：instances/my-fish/persona/identity.md。
- 页面短背景：instances/my-fish/memory/manual.md，保存后重启核心同步。
- 手写长记忆：instances/my-fish/memory/notes；00-核心记忆.md 每轮附带开头最多 1800 字符。
- 知识文章：instances/my-fish/knowledge；UTF-8 Markdown/TXT，可分子目录。
- 风格技能：instances/my-fish/persona/style-pack；人格与回复风格文件重启生效，其他规则/示例后续回复读取。
- 自动长期记忆：instances/my-fish/data/a-memorix；聊天历史：data/MaiBot.db。请用管理台管理，不手改数据库。

文件库使用本地中文双字/英文词匹配，通常 5 秒内重读变更，最多扫描 500 份、单份 2 MB、合计 20 MB，每轮选最多约 6000 字符。超限与编码问题显示在“我的资料库”。不是无限上下文，也不是完整向量知识库。上游自动记忆未配嵌入模型时检索能力受限，实际状态以完整管理台为准。

## 分享与二次开发

运行 scripts/build_release.py 或页面“生成纯净发行包”，按白名单生成独立 ZIP。在当前整理布局输出到“02-纯净分享版”；其他安装输出到上一层“导出分享版”。包中只有程序和模板，新使用者填写自己的账号与 API 后产生独立资料。不要压缩整个个人目录，不要分享备份。

## 0.3.3 识图与表情

管理层不再把模型强制设为纯文本。连接设置新增图片理解开关，开启后将当前模型标记为 visual，并在视觉任务为空时接到同一个聊天模型；已有独立视觉任务保留。DeepSeek deepseek-flash 可用，其他模型需自行确认图像支持。

scripts/import_nekowhale.py 可从 kiriyuki.com 与作者公开标注导入个人图库，不安装 DSH。来源与使用范围见实例图库中的“来源说明”。用户自己的背景、主人关系、授权、图库与数据库均排除在纯净包外。


## 0.3.3 表情回合与头像

表情成功发送后用原生终止标记结束当前回合；自有插件在拆句前和发送前阻止内部消息记录泄漏。动图头像过滤空白帧与纯色图，另支持独立 PNG 形象库和多模态预览。资料入口新增 10-PNG头像与美图，通用导入脚本 scripts/import_portraits.py 仅将图放入个人实例。来源见实例图库说明，PNG/头像和私人图库均不进发行包。
